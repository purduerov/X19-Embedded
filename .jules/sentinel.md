## 2024-09-05 - Buffer Overflow in CAN Serialization API
**Vulnerability:** The `x19_can_pack_*` functions in `shared/src/x19_can_protocol.c` copied payload structures (e.g. `x19_thruster_cmd_t`) into output `buffer`s using `memcpy` without verifying if the caller-provided buffer had sufficient capacity. The `size_t *len` argument was only used to return the packed size.
**Learning:** This existed because standard C array decay and lack of runtime bounds checking make it easy to assume caller buffer sizes. In this embedded telemetry architecture, not enforcing a capacity check could lead to a stack buffer overflow if a telemetry struct ever exceeded the `64`-byte CAN FD limit or a caller provided a small array.
**Prevention:** Always treat pointer-based buffer arguments with size checks. Use `size_t *len` as an IN/OUT parameter: initialize it with `sizeof(buffer)` before the call, and inside the function, assert `if (*len < sizeof(target_struct)) return X19_ERR_INVALID_ARG;`.
